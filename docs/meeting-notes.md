# 项目过程记录（会议纪要 / 迭代计划）

> 说明：本文件记录第九组在期末综合实践期间的计划、评审与决策，与报告 4.4 节的里程碑表相印证。

## 会议 1：选题与目标确认（2025-10-10）

* **参与人**：欧阳粤、童嘉豪
* **议题**：确定选题；确认现有系统基础与差距；制定迭代计划。
* **结论**：
  1. 选择候选题目 9「图书借阅管理系统」，基于已有 Books-Management 实验项目完善；
  2. 差距分析：现有系统只有 1 类后台角色、缺少押金审核闭环、密码明文、过程与测试文档缺失；
  3. 迭代划分 3 轮：第 1 轮补齐角色与权限、第 2 轮完善押金审核与密码安全、第 3 轮测试与文档。
* **行动项**：欧阳粤负责后端角色权限、数据库脚本；童嘉豪负责前端菜单与页面、测试用例与报告统稿。

## 会议 2：需求评审（2025-10-24）

* **参与人**：欧阳粤、童嘉豪
* **议题**：评审需求规格与用例模型；确认 3 类角色与 12 个功能点。
* **结论**：
  1. 确定角色为「普通读者 / 审核人员 / 管理员」，读者沿用 `base_member`；
  2. 审核人员职责限定为押金退还审核，避免权限过宽；
  3. 确认非功能需求：口令加密、接口鉴权、核心查询 ≤2s；
  4. 借阅状态、退款状态两个状态机定稿（见 `docs/requirements.md` 第 5 节）。
* **行动项**：更新需求文档；开始角色权限开发。

## 会议 3：设计与编码评审（2025-11-07）

* **参与人**：欧阳粤、童嘉豪
* **议题**：评审角色权限设计、数据库改动、前端菜单方案。
* **结论**：
  1. 采用 `@RequireRole` + 拦截器方案，角色从数据库实时读取；
  2. `sys_user` 增加 `role` 字段（varchar，存 ADMIN/REVIEWER），不单独建角色表，满足课程规模；
  3. 审核备注、审核人、审核时间必须留痕，审核人取自 token，禁止写死；
  4. 前端按角色过滤菜单，审核人员登录直达审核页；
  5. 读者密码改为 MD5 存储，与后台账号口径统一。
* **行动项**：欧阳粤实现后端；童嘉豪实现前端与数据库升级脚本。

## 会议 4：测试与验收（2025-11-14）

* **参与人**：欧阳粤、童嘉豪
* **议题**：测试执行情况、缺陷修复、报告与演示准备。
* **结论**：
  1. 单元测试 11 条全部通过；接口测试 18 条通过 17 条，1 条缺陷（审核重复提交）已修复；
  2. 遗留问题：负责人无真实任务看板截图，过程材料以本纪要 + 里程碑表呈现；
  3. 演示视频按“登录 → 借阅 → 退押金 → 审核 → 归还”流程录制。
* **行动项**：补齐测试报告、实践报告、使用说明。
