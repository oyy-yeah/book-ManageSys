## 1. 系统总体描述

### 1.1 建设背景

学校/社区图书室仍普遍使用 Excel 或纸质台账登记借还，存在三类突出问题：

1. **借还过程不可追踪**：借出时间、应还时间、逾期情况依赖人工记录，易漏记、难追溯；
2. **押金与退款不透明**：押金收取与退还缺少申请、审核、留痕的闭环，容易出现纠纷；
3. **运营数据无法沉淀**：借阅量、热门分类、用户活跃度等数据无法统计，采购与运营缺乏依据。

本系统以“图书—读者—借阅—押金”为核心对象，把借阅登记、押金管理、押金退还审核、统计分析搬到线上，
用可审计的状态流转替代人工台账。

### 1.2 系统参与者（3 类角色）

| 角色 | 说明 | 主要诉求 |
| --- | --- | --- |
| 普通用户（读者） | 使用读者端 Web 页面（或接口），对应 `base_member` 表 | 快速找到想借的书、在线借阅、押金可查可退、借阅记录可追溯 |
| 审核人员（REVIEWER） | 后台账号，负责借阅审核与押金退还审核 | 集中处理待审核借阅与退款申请、审核留痕 |
| 管理员（ADMIN） | 后台账号，系统最高权限 | 维护图书/分类/广告/账号、办理归还、查看统计报表 |

### 1.3 系统边界与运行环境

* **系统内**：读者账户、图书与库存、借阅单、押金与退款审核、评价、广告、后台账号与角色、统计报表；
* **系统外**：文件上传目录、短信/推送（不做）；不涉及小程序端与第三方支付；
* **运行环境**：服务端 Java 8 + MySQL 8.0，浏览器端 Chrome/Edge 等现代浏览器；接口采用 HTTP + JSON，JWT 鉴权。

## 2. 功能性需求

## 3. 非功能性需求

| NFR 编号 | 类别 | 需求描述（可验证） | 度量方式 |
| --- | --- | --- | --- |
| NFR-01 | 性能 | 核心查询（图书列表、借阅列表、押金申请列表）响应时间 ≤ 2s | 本机 Postman 计时，10 次取均值 |
| NFR-02 | 并发 | 支持 ≥ 50 个并发用户访问核心查询接口 | JMeter/Postman 并发压测 50 线程 |
| NFR-03 | 安全性 | 所有账号口令以 MD5 摘要存储，任何接口响应不返回密码摘要 | 查库与抓包检查 |
| NFR-04 | 安全性 | 接口按角色鉴权，越权访问返回 HTTP 403；未登录访问返回 401 | 用审核人员 token 调用管理员接口 |
| NFR-05 | 安全性 | 关键业务操作（审核）记录操作人 ID 与时间，可追溯 | 查询 `book_deposit_refund` 审核字段 |
| NFR-06 | 可靠性 | 借阅下单、归还、审核在事务内完成，异常时数据不中间态 | 代码 `@Transactional` + 异常注入测试 |
| NFR-07 | 易用性 | 后台菜单按角色展示，审核人员登录后直达审核工作台 | 角色登录演示 |
| NFR-08 | 可维护性 | 分层架构（Controller-Service-Dao），新增模块不改动既有代码 | 代码评审 |
| NFR-09 | 可移植性 | 通过配置切换数据库连接，构建产物可跨机器部署 | 修改 `application-dev.yml` 后启动 |
| NFR-10 | 兼容性 | 后台页面在 Chrome 90+/Edge 90+ 正常显示 | 浏览器验证 |

### 4.2 用例规约（UC-04 审核押金退还）

| 项目 | 内容 |
| --- | --- |
| 用例编号与名称 | UC-04 审核押金退还 |
| 参与者 | 审核人员（主）、管理员（辅） |
| 前置条件 | 审核人员已登录后台且账号状态正常；存在状态为“待审核”的押金退还申请 |
| 基本事件流 | 1. 审核人员登录，系统按角色展示“押金退还审核”菜单；<br>2. 审核人员打开申请列表，系统分页展示申请（读者、金额、申请时间、状态）；<br>3. 审核人员选中一条待审核申请，点击“通过”或“拒绝”；<br>4. 系统展示申请详情，审核人员填写审核备注并确认；<br>5. 系统校验申请仍为待审核状态，写入审核状态、审核人、审核时间；<br>6. 若通过，系统将该读者押金清零；<br>7. 系统提示审核成功并刷新列表。 |
| 扩展事件流 | 3a. 选中非待审核申请：提示“只能审核待审核状态的申请”；<br>5a. 申请已被其他审核人处理：提示“该申请已审核，不能重复审核”，不写库；<br>4a. 审核备注可为空。 |
| 后置条件 | 申请状态变为已通过/已拒绝，审核审计字段完整；通过时读者押金为 0。 |
| 异常 | 未登录访问返回 401；非审核/管理员角色访问返回 403。 |

### 4.3 其他核心用例（摘要）

* **UC-02 借阅图书**：前置条件读者已登录且押金>0；事件流为选择图书→确认借阅→系统校验库存→生成借阅单（14 天）→扣库存→写借阅历史；扩展：库存不足提示具体书名。
* **UC-03 申请退还押金**：前置条件押金>0 且无在途申请；事件流为发起申请→系统校验→生成待审核申请；扩展：已有在途申请则提示“正在处理中”。
* **UC-07 维护后台账号与角色**：管理员新增账号→填写用户名、密码、角色（管理员/审核人员）→系统校验角色合法性→密码 MD5 入库；扩展：角色非法拒绝保存。

## 5. 关键对象状态模型

### 5.1 借阅单（orderStatus）

```
[创建] --借阅下单--> (4 待审核) --审核通过--> (1 借阅中) --管理员归还--> (2 已归还) --读者评价--> (3 已评价)
                          |
                          +--审核拒绝--> (5 已拒绝)，并回补库存
                          |
                          +--读者取消--> (0 已取消)
```

### 5.2 押金退还申请（status）

```
[读者提交] --> (0 待审核) --审核通过--> (1 已通过)  （读者押金清零）
                    |
                    +--审核拒绝--> (2 已拒绝)  （押金保留，可再次申请）
```

规则：仅“待审核”状态可被审核；已通过/已拒绝为终态，不可回退。
